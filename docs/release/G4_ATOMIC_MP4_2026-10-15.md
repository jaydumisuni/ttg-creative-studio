# G4 — atomic MP4 export and failure preservation

15 October 2026 · Creative Studio only · product engineering acceptance

## The defect

Previously, `MotionExporter.export_mp4()` sent FFmpeg output directly to
the selected `final.mp4` filename. If FFmpeg failed, the disk filled, or
the process terminated partway through encoding, a partial MP4 could be left
behind or an existing approved export overwritten before completion.
The encoder's return code did not protect the destination from these
partial writes.

## Correction

The exporter writes an intermediate `.mp4` inside the **same destination
directory and filesystem** as the selected output. After FFmpeg completes
successfully, it checks that the file is nonempty, flushes its bytes to
disk and calls `os.replace()` to atomically publish the candidate.
The frame directory is still per-export and automatically removed.
Intermediate output is deleted on failure, including FFmpeg nonzero exit,
zero-byte output, timeout or an interrupted/disk-full atomic replacement.

The user's previous exported video is not changed until the complete
new candidate has passed the encoder and file-presence checks. This
provides filesystem atomicity; it is not a signed media artifact.

## Qualification

`scripts/test_studio_atomic_mp4.py` verifies:

- FFmpeg receives a temporary destination, not the user's final file.
- Nonzero FFmpeg exit propagates and preserves the previous MP4.
- Partial MP4 and scratch files are removed.
- Zero-byte output is rejected without replacing any prior export.
- Simulated ENOSPC during publication fails without corrupting the previous MP4.
- A successful candidate replaces the destination, leaving no temporary file.

Tests exercise real Studio frame rendering while substituting a controlled
encoder outcome to deterministically reproduce failures. The release workflow
runs the tests on **Windows Server and Ubuntu**. Separate existing
`test_studio_completion.py` checks real FFmpeg and AAC export when
available; mocked encoder bytes are **not claimed to be playable video**.

## Production boundaries

This closes a G4 data-integrity defect, not the complete G4 physical
acceptance gate. Hardware-side sustained exports, memory pressure,
accessibility and final owner visual approval remain separate.

No Ptah, REA, Oracle allowlist, signed-production PKI or model inference
service is changed.
